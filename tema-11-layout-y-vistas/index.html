Controller

Hereda de ControllerBase y suma las vistas. Si un controlador tiene que devolver las dos cosas, hereda de este.

GET sin parámetros

/Pacientes/Crearcontrolador Pacientes · acción Crear
public class PacientesController : Controller
{
    [HttpGet]
    public IActionResult Crear()
    {
        return View();
    }
}
  • Es lo que pide el navegador al escribir la URL o hacer clic en un link
  • [HttpGet] es opcional: una acción sin atributo responde a GET
  • Ponerlo aclara, y hace falta cuando hay otra Crear para POST

GET con un id en la ruta

/Pacientes/Detalle/3el tercer tramo es {id?}
// {controller=Home}/{action=Index}/{id?}
public IActionResult Detalle(int id)
{
    Paciente? paciente = repositorio.Obtener(id);
    if (paciente is null) return NotFound();

    return View(paciente);
}
  • El parámetro se tiene que llamar id, igual que en la ruta
  • ASP.NET convierte "3" en int solo
URLLlega
/Pacientes/Detalle/3id = 3
/Pacientes/Detalleid = 0 → 404
/Pacientes/Detalle/abcid = 0 → 404

GET con query string

/Pacientesruta
?texto=anaquery string
public IActionResult Index(string? texto)
{
    List<Paciente> pacientes =
        string.IsNullOrWhiteSpace(texto)
            ? repositorio.Listar()
            : repositorio.Buscar(texto);

    return View(pacientes);
}
  • Se vincula por nombre: texto en la URL → texto en el método
  • Si no viene, llega null
  • Varios: ?id=3&nombre=Carlos → Accion(int id, string nombre)
Un formulario con method="get" manda sus campos así, en la URL. Es lo que usa el buscador de pacientes.

POST con un formulario

Cada campo del formulario se asigna a la propiedad que se llama igual. A esto se le dice model binding.

Mostrar y recibir un formulario

// GET /Pacientes/Crear → el formulario vacío
[HttpGet]
public IActionResult Crear()
{
    return View();
}

// POST /Pacientes/Crear → los datos que cargó el usuario
[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Crear(Paciente paciente)
{
    int id = repositorio.Insertar(paciente);
    return RedirectToAction(nameof(Detalle), new { id });
}
  • Misma URL, dos acciones: el verbo decide cuál corre
  • El POST recibe un Paciente ya armado
Después de un POST, redirigir. Si devolviera una vista y el usuario recarga la página, el navegador manda el POST de nuevo y se inserta otro paciente.

Que los datos sean válidos (nombre obligatorio, DNI de 8 dígitos…) es el tema 13.

¿Dónde busca la vista?

Views/
├── Pacientes/         ← PacientesController
│   ├── Index.cshtml     ← acción Index
│   ├── Detalle.cshtml   ← acción Detalle
│   └── Crear.cshtml     ← acción Crear
├── Medicos/           ← MedicosController
│   └── Index.cshtml
└── Shared/            ← vistas de todos
    └── _Layout.cshtml

View() en PacientesController.Detalle busca:

  1. Views/Pacientes/Detalle.cshtml
  2. Views/Shared/Detalle.cshtml

Si no está en ninguna de las dos, error: The view 'Detalle' was not found, con las rutas donde la buscó.

Todos implementan IActionResult. Por eso la acción declara IActionResult: puede devolver uno u otro según el caso (polimorfismo, tema 03).

Las formas de View()

LlamadaVistaModelo

return View("Ficha");Ficha.cshtmlninguno

Se pasa el objeto (paciente), no la clase (Paciente). Si el modelo es un string, View("Ficha") lo toma como nombre de vista: para mandar un texto, View("Ficha", (object)texto).

¿Qué es Razor?

Una sintaxis para mezclar C# con HTML. Los archivos son .cshtml.

El C# corre en el servidor. El navegador recibe HTML común, igual que si lo hubiéramos escrito a mano.

Mandarle un modelo a la vista: @model

En el controlador

public IActionResult Detalle(int id)
{
    Paciente? paciente = repositorio.Obtener(id);
    if (paciente is null) return NotFound();

    return View(paciente);     // ①
}

En Detalle.cshtml

@model Paciente                 @* ② *@

<h1>@Model.Nombre</h1>          @* ③ *@
<p>Teléfono: @Model.Telefono</p>
  1. El controlador pasa el objeto en View(...)
  2. @model (minúscula), arriba de todo, dice de qué tipo es
  3. Model (mayúscula) es el objeto, con IntelliSense y control de tipos

El @: de HTML a C#

Implícita: @algo

<p>Hoy es @DateTime.Now.ToShortDateString()</p>
Hoy es 28/10/2026

Razor lee el C# hasta donde puede: un nombre, puntos, llamadas.

Explícita: @( … )

<p>En una semana: @(DateTime.Now.AddDays(7).ToShortDateString())</p>
<p>Total: @(precio * cantidad)</p>
<p>@(paciente.Telefono ?? "sin teléfono")</p>

Con paréntesis cuando hay espacios u operadores.

Sin paréntesis, @precio * cantidad muestra el precio y después el texto * cantidad.

Bloques @{ } y comentarios

@{
    ViewData["Title"] = "Inicio";
    var hoy = DateTime.Now;
    var saludo = hoy.Hour < 12 ? "Buen día" : "Buenas tardes";
}

<h1>@saludo</h1>

@* Un comentario de Razor: no llega al navegador *@
<!-- Uno de HTML: sí llega (se ve con "ver código fuente") -->
  • @{ } ejecuta C# y no muestra nada
  • Las variables que declara se usan más abajo en la vista
  • Que sea poco: la lógica va en el controlador, no en la vista

@if y @foreach

@model List<Paciente>

@if (Model.Count == 0)
{
    <p>No hay pacientes.</p>
}
else
{
    <ul>
        @foreach (var paciente in Model)
        {
            <li>@paciente.Nombre</li>
        }
    </ul>
}
<ul>
    <li>Ana Gómez</li>
    <li>Bruno Díaz</li>
    <li>Carla Ruiz</li>
    <li>Diego Herrera</li>
    <li>Mariana Paz</li>
</ul>

Dentro de las llaves, una etiqueta HTML (<li>) vuelve a modo HTML. También están @for, @while y @switch.

Razor codifica lo que muestra

Alguien carga un paciente con este nombre:

<script>alert("hackeado")</script>

Con @paciente.Nombre

&lt;script&gt;alert(&quot;hackeado&quot;)&lt;/script&gt;

El navegador lo muestra como texto. No se ejecuta.

Con @Html.Raw(paciente.Nombre)

<script>alert("hackeado")</script>

Se ejecuta en el navegador de quien abra la página.

Es la misma idea que los parámetros contra la inyección SQL (tema 08), pero del lado del HTML. No usar Html.Raw con datos que cargó un usuario.

Tag helpers

Atributos asp-… en etiquetas HTML comunes, que Razor completa en el servidor.

@* lo que escribimos *@
<a asp-controller="Pacientes" asp-action="Index">Pacientes</a>

<!-- lo que llega al navegador -->
<a href="/Pacientes">Pacientes</a>
  • La URL la arma el ruteo: si cambia, los links se actualizan solos
  • Menos errores de tipeo en las rutas
  • Los formularios se vinculan con las propiedades del modelo
  • Se ve como HTML: lo puede leer quien diseña

Se habilitan en Views/_ViewImports.cshtml: @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

Links con asp-route

RazorHTML que se genera
<a asp-controller="Medicos" asp-action="Index"><a href="/Medicos">
<a asp-action="Crear"><a href="/Pacientes/Crear"> (controlador actual)
<a asp-action="Detalle" asp-route-id="@paciente.Id"><a href="/Pacientes/Detalle/3">
<a asp-action="Index" asp-route-texto="ana"><a href="/Pacientes?texto=ana">

asp-route-id

id está en la plantilla de la ruta ({id?}): va como tramo de la URL.

asp-route-texto

texto no está en la plantilla: va en la query string.

Del lado del controlador llegan igual: un parámetro int id o string texto.

El tag helper de formulario

Razor

<form asp-action="Crear" method="post">
    …
</form>

HTML generado

<form action="/Pacientes/Crear" method="post">
    …
    <input name="__RequestVerificationToken"
           type="hidden" value="CfDJ8…" />
</form>
  • asp-action (y asp-controller) arman el action
  • Con method="post" agrega un token antifalsificación oculto
Con [ValidateAntiForgeryToken] en la acción POST, el servidor rechaza los envíos que no traen ese token: un formulario de otro sitio no puede hacerse pasar por el nuestro (ataque CSRF).

Campos con asp-for

@model Paciente

<label asp-for="Nombre"></label>
<input asp-for="Nombre" />
<label for="Nombre">Nombre</label>
<input type="text" id="Nombre" name="Nombre" value="" />

El name es el que usa el model binding para llenar Paciente.Nombre en el POST.

El type sale del tipo de la propiedad:

Tipo en C#HTML
stringtype="text"
int, byte, double…type="number"
booltype="checkbox"
DateTimetype="datetime-local"

Con atributos como [DataType(DataType.Password)] o [EmailAddress] cambia el tipo: lo vemos en los temas 12 y 13.

Todo junto: Crear.cshtml

@model Paciente
@{
    ViewData["Title"] = "Nuevo paciente";
}

<h1>Nuevo paciente</h1>

<form asp-action="Crear" method="post">
    <label asp-for="Nombre"></label>

    <label asp-for="DNI"></label>

El layout

Una vista que define la estructura común de todas las páginas.

  • El <head>, el CSS, el menú, el pie: una sola vez
  • Cada vista aporta solo su parte
  • Cambiar el menú es cambiar un archivo

_Layout.cshtml y @RenderBody()

<!DOCTYPE html>
<html lang="es">
<head>
    <title>@ViewData["Title"] · Clínica</title>
    <link rel="stylesheet" href="~/css/sitio.css" />
</head>
<body>
    <header>
        <a asp-controller="Pacientes" asp-action="Index">Pacientes</a>
        <a asp-controller="Medicos" asp-action="Index">Médicos</a>
    </header>

    <main>
        @RenderBody()
    </main>

    <footer>Taller de Lenguajes 2 · @DateTime.Now.Year</footer>
</body>
</html>
@RenderBody() marca dónde se dibuja la vista que eligió el controlador. Tiene que estar una vez.
  • Las vistas ya no llevan <html> ni <head>: solo su contenido
  • ~/ es la raíz del sitio: wwwroot

El título de cada página

La vista lo pone…

@* Views/Pacientes/Index.cshtml *@
@{
    ViewData["Title"] = "Pacientes";
}

…y el layout lo usa

@* Views/Shared/_Layout.cshtml *@
<title>@ViewData["Title"] · Clínica</title>
Pacientes · Clínica
Funciona porque la vista se ejecuta antes que el layout. ViewData es un diccionario que comparten el controlador, la vista y el layout.

ViewData["…"] sirve para datos sueltos como este. Para los datos de la página, mejor un modelo con tipo: es el tema 12, ViewModels.

@RenderSection: más de un hueco

En el layout

    …
    <footer>…</footer>

    @await RenderSectionAsync("Scripts", required: false)
</body>

required: false: las vistas que no la definen no dan error.

En Crear.cshtml

<form …>…</form>

@section Scripts {
    <script>
        document.getElementById("Nombre").focus();
    </script>
}

Este script se dibuja al final del <body>, no donde está escrito.

También existe la forma sincrónica, @RenderSection("Scripts", required: false), que es la que traen plantillas más viejas.

Los archivos especiales

ArchivoPara qué
Views/Shared/Vistas que usan varios controladores. Si una vista no está en la carpeta del controlador, se busca acá
Shared/_Layout.cshtmlLa «plantilla maestra»: estructura de todas las páginas
Shared/Error.cshtmlLa página que se muestra cuando algo falla (la trae la plantilla)
Views/_ViewStart.cshtmlCorre antes de cada vista. Elige el layout: @{ Layout = "_Layout"; }
Views/_ViewImports.cshtml@using y @addTagHelper para todas las vistas

El _ al principio es una convención: son vistas que no se piden directamente por URL. Una vista puede cambiar su layout, o no usar ninguno, con @{ Layout = null; }.

wwwroot: los archivos estáticos

wwwroot/
├── css/
│   └── sitio.css      ← nuestro CSS
├── js/
│   └── sitio.js       ← nuestro JavaScript
├── img/
└── lib/               ← de terceros: Bootstrap, jQuery…
  • Lo que está acá se manda tal cual, sin pasar por un controlador
  • wwwroot/css/sitio.css → /css/sitio.css
  • Lo habilita app.UseStaticFiles() en Program.cs. Las plantillas nuevas usan app.MapStaticAssets(), que además comprime y cachea
Lo que está fuera de wwwroot (el código, appsettings.json, la base) no se puede pedir por URL.
