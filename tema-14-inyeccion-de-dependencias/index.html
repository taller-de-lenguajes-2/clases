¿Qué es una dependencia?

Si una clase A usa a una clase B, A depende de B: la necesita para funcionar.

  • TurnosController depende de TurnoRepository
  • TurnoRepository depende de la cadena de conexión
  • AutenticacionService depende de UsuarioRepository

No es malo: las clases tienen que colaborar. El tema es cómo consigue A su B.

Una impresora y su cartucho

La impresora crea su cartucho

public class Impresora
{
    private readonly CartuchoNegro cartucho = new();

    public void Imprimir(Papel papel)
    {
        cartucho.Usar(papel.Texto.Length);
        Console.WriteLine(papel.Texto);
    }
}
  • ¿Y si quiero imprimir en color? Hay que cambiar Impresora
  • ¿Y para probarla sin gastar tinta? No se puede

Le pasan el cartucho desde fuera de la clase

public class Impresora(ICartucho cartucho)
{
    public void Imprimir(Papel papel)
    {
        cartucho.Usar(papel.Texto.Length);
        Console.WriteLine(papel.Texto);
    }
}

var enBlanco = new Impresora(new CartuchoNegro());
var enColor  = new Impresora(new CartuchoColor());

La impresora no sabe qué cartucho tiene: sabe que es un ICartucho. Igual que una impresora de verdad.

Inyectar en vez de crear

La inyección de dependencias es darle a un objeto, desde afuera, lo que necesita, en lugar de que lo cree él mismo.

Crea su dependencia

public class TurnosController : Controller
{
    private readonly TurnoRepository turnos =
        new TurnoRepository("Data Source=clinica.db");
}

El controlador sabe que es SQLite, dónde está el archivo y cómo se arma el repositorio.

La recibe

public class TurnosController(ITurnoRepository turnos)
    : Controller
{
    …
}

El controlador solo sabe que recibe algo que sabe listar e insertar turnos.

Lo más común es inyectar por el constructor: sin la dependencia, el objeto no se puede crear.

La D de SOLID: inversión de dependencias

  1. Los módulos de alto nivel (lo que decide) no dependen de los de bajo nivel (los detalles). Los dos dependen de abstracciones.
  2. Las abstracciones no dependen de los detalles: los detalles dependen de las abstracciones.

La inyección de dependencias es la técnica para cumplir este principio: alguien de afuera decide qué implementación recibe cada clase.

¿Para qué sirve?

Desacoplamiento

Una clase no sabe cómo se crean sus dependencias: se las dan (tema 10).

Cambiar implementaciones

SQLite por SQL Server, un repositorio real por uno de prueba: cambia una línea.

Mantenibilidad

Cómo se arma todo está en un solo lugar: Program.cs.

Pruebas

Para probar el controlador se le pasa un repositorio falso, sin base de datos.

El contenedor de .NET

En vez de que cada clase cree sus dependencias, un contenedor las crea y las entrega. A eso se le dice inversión de control.

1 · Registrar

En Program.cs: para tal interfaz, tal clase, con tal tiempo de vida

→

2 · Recibir

La clase lo pide en su constructor; .NET se lo pasa

Paso 1: registrar

builder.Services.AddScoped<ITurnoRepository, TurnoRepository>();
ParteQué es
builder.ServicesEl contenedor de servicios de la aplicación
AddScopedEl tiempo de vida: cuánto dura cada objeto (más adelante)
ITurnoRepositoryLo que se pide: la interfaz
TurnoRepositoryLo que se entrega: la clase que la implementa
builder.Services.AddSingleton<IUsuarioRepository, UsuarioRepository>();
builder.Services.AddScoped<IAutenticacionService, AutenticacionService>();
builder.Services.AddScoped<ServicioIntermedio>();     // sin interfaz: se pide por la clase

Paso 2: recibir en el constructor

Constructor primario (C# 12)

    ITurnoRepository turnos,
    IPacienteRepository pacientes,

La forma clásica

El controlador no sabe qué clase recibe ni cómo se creó. Solo sabe qué puede hacer con ella.

Los tres tiempos de vida

Cuando una clase pide un servicio, ¿el contenedor crea uno nuevo o le da uno que ya tenía?

Transient

Uno nuevo cada vez que se pide.

AddTransient

Scoped

Uno por request: todos los que lo piden en el mismo request comparten el mismo.

AddScoped

Singleton

Uno solo para toda la aplicación, hasta que se reinicia.

AddSingleton

¿Cuál usar?

ParaEn la clínica
TransientServicios livianos, sin estado, que hacen un cálculo o una transformación y listoun servicio que arma el texto de un recordatorio de turno
ScopedLo que tiene que ser el mismo durante todo un request: repositorios, servicios que usan la sesión o una transacciónPacienteRepository, AutenticacionService
SingletonLo que es caro de crear o guarda algo para toda la aplicación: configuración, caché, datos en memoriaUsuarioRepository (la lista en memoria)
Ojo con el Singleton: lo comparten todos los usuarios al mismo tiempo. Si guarda algo de un usuario (el paciente que está mirando), lo ve el resto.

Errores comunes

No registrado

Unable to resolve service for type
'ITurnoRepository' while attempting
to activate 'TurnosController'.

Se pide algo que no está en Program.cs. El más frecuente.

Dependencia circular

A pide B y B pide A: el contenedor no puede crear a ninguno y tira una excepción.

Suele indicar que a alguna clase le sobran responsabilidades.

Dependencia cautiva

Un Singleton que recibe un Scoped: se queda con el del primer request para siempre.

En Development, .NET lo detecta y no arranca.

Regla: un servicio solo puede recibir servicios que vivan igual o más que él.
