Abstracción

Abstraer es representar algo del mundo real quedándonos solo con lo que nos interesa para nuestro sistema, y omitiendo todo lo demás. Tres preguntas guían el recorte:

1

¿Qué es?

La entidad del mundo real que vamos a modelar.

2

¿Qué representa?

El rol que cumple dentro de nuestro sistema.

3

¿En qué contexto?

La misma entidad se abstrae distinto en sistemas distintos.

No existe la abstracción correcta: depende de para qué la necesitamos. La pregunta es siempre: ¿con qué nos quedamos?

Anatomía de una clase

public class Auto
{
    // ① campos — el estado
    private string marca;
    private int velocidad;
    // ② constructor
    public Auto(string nuevaMarca)
    { marca = nuevaMarca; velocidad = 0; }
    // ③ propiedad
    public int Velocidad
    { get { return velocidad; } }
    // ④ método — el comportamiento
    public void Acelerar(int aceleracion)
    { velocidad += aceleracion; }
}

① Campos (atributos) — el estado del objeto. Variables de instancia: cada objeto tiene sus propios valores.

② Constructor — método especial que corre al hacer new: inicializa el objeto y lo deja en un estado válido y consistente. Un Auto nunca nace sin marca.

③ Propiedades — acceso controlado a los campos (get / set): qué se puede leer o modificar desde afuera.

④ Métodos — el comportamiento: cambiar el estado, calcular, interactuar con otros objetos.

Encapsulamiento y ocultamiento

Sobre la abstracción aplicamos el encapsulamiento: envolver datos y acciones como una unidad, y decidir qué mostramos y qué ocultamos.

  • Ocultamos / bloqueamos lo que no debe verse desde afuera: el estado interno, los detalles de implementación
  • Presentamos / exponemos la interfaz pública: lo único que el resto de las clases puede ver y utilizar
Esto es el principio de ocultamiento de información: cada clase decide qué muestra y qué guarda para sí.

Un ejemplo: el conductor

  • Mostramos lo que el otro necesita para usar el objeto: al conductor le damos volante, pedales y tablero
  • Ocultamos el funcionamiento interno: la inyección, la mezcla, la ECU — nadie los toca desde afuera
  • El conductor usa el auto sin saber cómo funciona por dentro — y no puede romper lo que no ve

Modificadores de acceso

  • public — el miembro es visible desde cualquier clase
  • private — el miembro solo es visible dentro de su propia clase
Regla práctica: campos privados, accedidos mediante propiedades o métodos públicos. Así la información se mantiene consistente y aumenta la cohesión.
public class Empleado
{
    private decimal sueldo;      // oculto

    public string Nombre { get; set; }

    public decimal CalcularAguinaldo()
    {
        return sueldo / 2;
    }
}

Miembros de instancia y estáticos

public class Auto
{
    public string Marca { get; set; }   // de instancia

    public static int Cantidad;         // estático

    public Auto(string marca)
    {
        Marca = marca;
        Cantidad++;
    }
}

var a = new Auto("Fiat");
var b = new Auto("Ford");
Console.WriteLine(a.Marca);        // "Fiat"
Console.WriteLine(Auto.Cantidad);  // 2
  • De instancia: cada objeto tiene su propio valor → se accede desde el objeto: a.Marca
  • Estáticos: pertenecen a la clase, no a un objeto → se accede con el nombre de la clase: Auto.Cantidad, incluso sin instancias
De un miembro estático existe una sola copia, sin importar cuántas instancias de la clase se creen.

Métodos y su firma

Un método es un bloque de código con una serie de instrucciones que representa el comportamiento del objeto. Se invoca con objeto.Metodo(...).

public void Acelerar(int aceleracion)
{
    velocidad += aceleracion;
    if (velocidad > velocidadMaxima)
        velocidad = velocidadMaxima;  // tope físico
}

public void Frenar()
{
    // frena de a poco, no de golpe
    while (velocidad > 0)
        velocidad = velocidad - 5;

    velocidad = 0;  // nunca queda negativa
}
Auto auto = new Auto("Fiat");
auto.Acelerar(10);
auto.Frenar();  // 10 → 5 → 0

Nombre del objeto + punto + método + paréntesis.

Firma = nombre (Acelerar) + parámetros (int). El tipo de retorno no forma parte de la firma.

El que llama a Frenar() no sabe (ni le importa) que adentro hay un while: solo conoce la firma.

Sobrecarga de un método

public class Auto
{
    private int velocidad;

    // método a
    public void Acelerar(int aceleracion) { … }

    // método b
    public void Acelerar(string aceleracion) { … }

    // método c
    public void Acelerar(int aceleracion, int segundos) { … }
}

Varios métodos con el mismo nombre y distinto tipo o número de argumentos — es decir, distinta firma. El compilador elige cuál ejecutar según los argumentos.

auto.Acelerar(10);                 // → a
auto.Acelerar("10");               // → b
auto.Acelerar(10, 3);              // → c
auto.Acelerar(Console.ReadLine()); // → b

El constructor

Método cuyo nombre es igual al nombre de su tipo, sin tipo de retorno. Se ejecuta al hacer new. También se puede sobrecargar: distintas formas de inicializar un objeto.

public class Auto
{
    private string marca;
    private int velocidad;

    // constructor a
    public Auto() { marca = "sin marca"; }

    // constructor b
    public Auto(string nuevaMarca)
    { marca = nuevaMarca; }
}
var a1 = new Auto();
// → a: "sin marca", velocidad 0

var a2 = new Auto("Fiat");
// → b
La sobrecarga de constructores da versatilidad al instanciar y muchas veces reduce código.
