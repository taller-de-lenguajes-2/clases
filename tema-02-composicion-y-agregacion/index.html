Composición y agregación

Cómo se asocian las clases para construir una aplicación

Construyendo un sistema

Una aplicación orientada a objetos está constituida por múltiples clases que interactúan entre sí por medio de mensajes.

  • Cada clase es una abstracción con una responsabilidad clara
  • Las clases colaboran enviándose mensajes (llamando métodos)
  • Todas juntas proveen el comportamiento esperado de la aplicación
A la estructura, funcionamiento e interacción entre las partes la llamamos arquitectura — como los planos de un edificio.

¿Cómo podemos vincular clases?

Para que el bar funcione, sus clases tienen que estar conectadas. Una asociación es una relación donde una clase contiene a otra: una clase es miembro de otra clase.

  • Se implementa declarando un miembro cuyo tipo es otra clase
  • Hay dos tipos de asociación: composición y agregación
public class Bar
{
    // el Bar contiene una Cocina…
    private Cocina cocina;

    // …varios Mozos y sus Clientes
    private List<Mozo> mozos;
    private List<Cliente> clientes;
}

¿Todas estas relaciones son iguales? No — y esa es justamente la diferencia entre composición y agregación.

Composición — “es parte de”

  • Es la relación más fuerte entre clases
  • El objeto contenido no puede existir independientemente del que lo contiene
  • El tiempo de vida del miembro está condicionado por el del contenedor
La Cocina es parte del Bar: nace cuando el bar se construye y muere con él.
public class Bar
{
    // la Cocina nace y muere con el Bar
    private Cocina cocina = new Cocina();
}

Agregación — “tiene un”

  • Relación más débil que la composición
  • El objeto contenido puede existir con independencia del que lo contiene
  • El objeto llega desde afuera: ya existía antes de asociarse
El Bar tiene Clientes: si el bar cierra, los clientes siguen existiendo.
public class Bar
{
    // los clientes existen fuera del Bar
    private List<Cliente> clientes = new();

    public void Entra(Cliente cliente)
    {
        clientes.Add(cliente);
    }
}

La diferencia clave: el ciclo de vida

¿Qué pasa con el objeto contenido cuando el contenedor deja de existir?

Otros ejemplos clásicos

◆ Composición — “es parte de”

  • El Salón es parte de un Colegio
  • El Corazón es parte de una Persona
  • La Habitación es parte de una Casa

◇ Agregación — “tiene un”

  • El Curso tiene Estudiantes
  • El Equipo tiene Jugadores
  • La Playlist tiene Canciones
La pregunta que decide: si destruyo el contenedor, ¿el contenido tiene sentido por sí solo? Si la respuesta es sí → agregación.

¿Cuál es cuál? — Vehículo

public class Vehiculo
{
    public Motor MotorDeVehiculo { get; set; }
    public List<Rueda> Ruedas { get; set; }

    public void Acelerar() { … }
    public void Frenar() { … }
}
  • El Motor forma parte del Vehículo → composición ◆
  • El Vehículo tiene Ruedas que pueden cambiarse y reutilizarse → agregación ◇
